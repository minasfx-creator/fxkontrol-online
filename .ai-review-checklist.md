# FXKontrol AI Review Checklist

Antes de aceitar qualquer PR, verificar:

## Persistência
- `saveProject()` salva positions, timelineItems, trajectories e waypoints.
- `loadProject()` substitui o estado inteiro, sem append.
- Não há risco de duplicação ao carregar o mesmo projeto duas vezes.

## Segurança
- Nenhum segredo hardcoded.
- Nenhum `.env` real versionado.
- Variáveis críticas falham cedo se ausentes (envGuard runtime fail-fast).

## Supabase / PWA
- Não cachear respostas autenticadas do Supabase (`/rest/v1`, `/functions/v1`).
- Cache permitido apenas para assets públicos (JS/CSS/imagens estáticas).

## Billing
- Paddle nunca assume `live` por padrão.
- Token ausente gera erro explícito (sem fallback silencioso).
- `environment` column sempre filtrada nas queries de subscription.

## Runtime
- Nenhum `setInterval` global em `src/store` ou `src/lib` sem start/stop.
- Timers precisam ter lifecycle controlado (cleanup em unmount/HMR).

## Safety (FXKontrol-specific)
- `safety_gate_strict` permanece ON em produção.
- E-STOP latency <50ms preservada.
- Command path UI → ShowPlan → CommandBus → SafetyStateMachine → FieldBus intacto.

## Qualidade
- Sem `any` desnecessário.
- Sem `console.warn` para erro crítico (usar `console.error` + telemetry).
- Sem `eslint-disable` sem justificativa em comentário.

## Scripts package.json esperados
O pipeline roda os comandos abaixo. Se `package.json` for editável no seu fork,
adicione estes scripts (no Lovable o arquivo é gerenciado e não pode ser editado
diretamente — o pipeline já usa fallbacks `npx vitest run --coverage` e
`npx tsc --noEmit`):

```json
{
  "scripts": {
    "typecheck": "tsc --noEmit",
    "test:coverage": "vitest run --coverage",
    "quality": "npm run typecheck && npm run lint && npm run test:coverage && npm run build"
  }
}
```
